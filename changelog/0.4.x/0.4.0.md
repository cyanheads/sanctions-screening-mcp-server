# 0.4.0 — 2026-09-25

Upgrading: run `bun run mirror:init` once. Mirrors written by 0.3.0 or earlier have no GLEIF checkpoint, so until then `sanctions_resolve_entity` searches legal names only (its notice says alternate names are not yet indexed), trace parent levels without a relationship read `unknown`, `mirror:refresh` exits non-zero naming `mirror:init`, and the HTTP cron logs the gap each run. Rolling back to 0.3.0 is safe: it opens and serves a mirror 0.4.0 wrote, and 0.4.0 needs another `mirror:init` after a GLEIF write by 0.3.0.

## Added

- **`alternateNames`** on `sanctions_get_entity` and `sanctions://entity/{lei}` ([#24](https://github.com/cyanheads/sanctions-screening-mcp-server/issues/24)): every other and transliterated name with its GLEIF `type`. A record stored by 0.3.0 reads its bare `otherNames` as `UNKNOWN`.
- **`matchedNameType`** on `sanctions_resolve_entity` matches (#24): `LEGAL_NAME`, a GLEIF name type such as `TRADING_OR_OPERATING_NAME`, or `UNKNOWN`.
- **`parentStatus`** on `sanctions_trace_ownership` nodes whose parents the walk read ([#26](https://github.com/cyanheads/sanctions-screening-mcp-server/issues/26)): `direct` and `ultimate`, each `relationship`, `exception` with its `exceptionReasons` (e.g. `NATURAL_PERSONS`), `none`, or `unknown` when reporting exceptions are not loaded.
- **`reportingExceptionsLoaded`** on `sanctions_trace_ownership`, `sanctions_list_sources`, and `sanctions://sources`, plus `reportingExceptionCount` on the `gleif` source row once loaded (#26).

## Changed

- **`status: "lapsed"` matches exactly `LAPSED`** on `sanctions_resolve_entity` ([#23](https://github.com/cyanheads/sanctions-screening-mcp-server/issues/23)); `RETIRED`, `DUPLICATE`, `ANNULLED`, `PENDING_*`, and `MERGED` now need `status: "any"`. Level 1 `status` is stored from `RegistrationStatus` only, never `EntityStatus`.
- **The HTTP refresh cron applies GLEIF deltas after the sanctions lists** ([#49](https://github.com/cyanheads/sanctions-screening-mcp-server/issues/49)), under the same 4-hour bound; a gap that needs `mirror:init` is logged at error level and never attempted. `SANCTIONS_REFRESH_SKIP_GLEIF=1` skips this leg too and is now declared in `server.json`.
- **`mirror:init` also loads the reporting-exceptions golden copy and builds the GLEIF name index** (#24, #26, #49), then records the checkpoint: about 6.4M more rows (~525 MiB) and ~0.8 GB of index.
- **`mirror:verify`** adds `reportingExceptions`, `alternateNamesIndexed`, and `checkpoint` to the GLEIF line.
- **Empty-result notices on `sanctions_screen_name` and `sanctions_resolve_entity` no longer suggest `matchMode: "fuzzy"`** ([#36](https://github.com/cyanheads/sanctions-screening-mcp-server/issues/36)), since an empty strict pass already falls back to fuzzy.
- **`sanctions_vet_counterparty`** names GLEIF parents as accounting-consolidation parents, not beneficial owners, has a reporting exception's reasons reported instead of "no parent", and no longer asks for a fuzzy retry (#26, #36).
- **`complete` on `sanctions_trace_ownership`** is described as covering the loaded relationships only (#26); its value is computed as before.
- **Docs:** `README.md` and `docs/design.md` cover the checkpointed refresh, the GLEIF name index, parent status, and the upgrade path.

## Fixed

- **GLEIF refresh no longer skips gaps or deletions** (#49): per dataset, `mirror:refresh` streams the smallest delta window (`IntraDay` to `LastMonth`) that reaches back to the stored checkpoint and applies `gleif:Deletion` markers. `leiAsOf` and the checkpoint advance only once every dataset has applied.
- **A GLEIF gap deltas cannot cover fails instead of reporting fresh** (#49): with no checkpoint, or one older than `LastMonth`, `mirror:refresh` applies nothing to GLEIF and exits non-zero naming `mirror:init`.
- **A failed sanctions list no longer skips the GLEIF leg** (#49); the run still exits non-zero.
- **`sanctions_resolve_entity` reaches other and transliterated names** (#24): previous, trading, alternative-language, and ASCII-transliterated names take part in matching, one candidate per LEI, and an exact alternate-name match outranks a strong legal-name match.
- **LEI name resolution no longer scans the entity table per query word** ([#33](https://github.com/cyanheads/sanctions-screening-mcp-server/issues/33)): strict and fuzzy passes read the FTS5 `lei_name` index, fuzzy blocking by token prefix.
- **A country `jurisdiction` includes its subdivisions** (#36): `US` matches `US-DE` and `US-CA`, and ISO 3166-2 codes are accepted and matched exactly, case-insensitive.
