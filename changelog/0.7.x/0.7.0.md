# 0.7.0 — 2026-11-19

## Added

- **Native-script names** ([#87](https://github.com/cyanheads/sanctions-screening-mcp-server/issues/87)): UK `NameNonLatinScript` and UN `NAME_ORIGINAL_SCRIPT` are stored as aliases (UK `aka`, UN `primary`; `primaryName` is unchanged), so screens in those scripts match. A strict screen of a name holding a letter outside the Latin script completes the UK and UN lists even where strict matched them; every other list stays settled by its strict hit. Stored from the first sanctions refresh by this release.
- **`sanctions_list_sources`** ([#88](https://github.com/cyanheads/sanctions-screening-mcp-server/issues/88)): each sanctions row carries `lastHarvestedAt` (the list's last successful harvest, UTC) and `publishedAt` (the publisher's stamp on the document, not when the list content last changed), and `lastRefresh` (`status`, `startedAt`, `failedSources`) appears while a refresh is `in_progress` or failed. A refresh reads `in_progress` until the index rebuild that records its per-list outcomes commits. `sanctions://sources` serves the same payload. Both row fields are absent until a list's first harvest by this release.
- **UN reference numbers** ([#89](https://github.com/cyanheads/sanctions-screening-mcp-server/issues/89)): `unReferenceNumber` on `uk` and `eu` designations, in `sanctions_get_designation`, the designation resource, and `sanctions_screen_name` hits, and UK `SanctionsImposed` and `DesignationSource` as `features`, one per `|`-separated part. `sanctions_get_designation` accepts a UN reference number as `entryId` on `uk` and `eu` after the entry ID and the list's own reference number miss, then in any zero padding (`LYi.28`, `LYi.028`), with stored values kept as published; two designations carrying one fail `reference_ambiguous`. `designation_not_found` points a UN reference number at source `un` only when the lookup named another list. Stored from the first sanctions refresh by this release; until then a UN reference lookup on `uk` or `eu` is `designation_not_found`.
- **Legal-form spellings** ([#90](https://github.com/cyanheads/sanctions-screening-mcp-server/issues/90)): a strict name screen, including the `sanctions_get_entity` and `sanctions_trace_ownership` (`screenNodes`) cross-references, counts a legal form as present in any spelling of the same form (`Ltd`/`Limited`, `LLC`/`OOO`). The table holds thirteen forms; `LP` and `PLC` are forms of their own, a non-public joint stock company reads as `JSC`, `Limited Liability Corporation` or a bare `Limited Liability` reads as `LLC`, and a longer form never matches as a word of another form. A name equal only up to legal-form spelling is `strong`.
- **Sound matches** ([#92](https://github.com/cyanheads/sanctions-screening-mcp-server/issues/92)): a query word counts as covered when its primary Double-Metaphone key (three or more characters) equals a candidate word's (`gaddafi`, `qadhafi`), in `queryTokenCoverage.covered` and a strict screen's completion pass; `queryTokenCoverage.phonetic` counts them, and equal coverage ranks spelling above sound. A sound match never admits a candidate to a fuzzy screen and never raises a score.
- **`sanctions_get_entity`** and `sanctions://entity/{lei}` ([#94](https://github.com/cyanheads/sanctions-screening-mcp-server/issues/94)): `entityStatus`, `successors` (each a `lei`, a `name`, or both), and `entityStatusLoaded`; `sanctions_list_sources` reports a mirror-wide `entityStatusLoaded`. Stored for records this release loads: on a mirror an earlier release wrote, a delta fills only the records it carries, and the mirror-wide flag turns true only after a completed golden-copy load (`mirror:init`).

## Changed

- **Breaking: `sanctions_trace_ownership` no longer returns `byteTargetExceeded`** ([#91](https://github.com/cyanheads/sanctions-screening-mcp-server/issues/91)). In 0.6.1 the field was a required boolean on every page, and a page stopped after the record that took it to the 64-KiB target. Every page but the last now holds exactly `limit` records, and the field is gone from the output and its schema.
- **Breaking: a `sanctions_trace_ownership` cursor** that carries a key the server did not write, at its top level or inside its `query`, is refused with `invalid_cursor`; 0.6.1 dropped the key and answered with the page. Cursors the server issued, 0.6.1's included, resume unchanged.
- **`sanctions_get_entity`** escapes Markdown characters in GLEIF names in `content[]`; `structuredContent` is unchanged.
- **`mirror:verify`** prints each list's harvest time and document date and the lists that failed in the last refresh, and reports the refresh status `sanctions_list_sources` reports.
- **Server instructions** and the `sanctions_vet_counterparty` prompt name each list's harvest and document dates; the prompt no longer mentions `byteTargetExceeded`.

## Fixed

- **EU `primaryName`** is a Latin-script name where the entity publishes one, instead of whichever language's alias the list prints first ([#93](https://github.com/cyanheads/sanctions-screening-mcp-server/issues/93)); the replaced alias stays in `aliases`. Applies from the first sanctions refresh by this release.
- **A self-closing record element** in a source document no longer ends that document's harvest early; 0.6.1's scanner waited for a closing tag that never came and dropped every later record.
- **The streaming XML record scanner's** cost grows linearly with document size.
