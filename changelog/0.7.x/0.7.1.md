# 0.7.1 — 2026-11-25

## Changed

- **Romanized read** ([#99](https://github.com/cyanheads/sanctions-screening-mcp-server/issues/99)): a strict screen of a Russian-alphabet name also reads each other list it matched, UK and UN excepted, for names holding every word of the romanization as a whole word, returned `approximate` with the lists in `fuzzySources`. A name is kept only when one comparison form holds a word for each native word by exact spelling (`Мэр Мер` reads `Mer Mer`, never `Mer Trading`), and `totalAvailableBasis` stays `exact`.
- **Public-company spellings** ([#101](https://github.com/cyanheads/sanctions-screening-mcp-server/issues/101)): `Public Company Limited`, `Public Company Ltd`, and `Public Ltd` read as `PLC` in a strict screen, so a `PLC` query returns those designations as `strong` and the reverse. A query and a stored name are read both as `plc` and word by word, so every 0.7.0 strict hit stays (`Public Company Limited Ltd` keeps its hits, as does a stored `X Public Co Ltd` against `X Public Company Limited`).

## Fixed

- **List and GLEIF text** ([#96](https://github.com/cyanheads/sanctions-screening-mcp-server/issues/96)): names, addresses, remarks, and other published text reach `content[]` through `escapeMarkdownInline`, so Markdown syntax in a value reads back as text; `structuredContent` is unchanged, and the server instructions describe the encoding.
- **Markdown lists** ([#96](https://github.com/cyanheads/sanctions-screening-mcp-server/issues/96)): `sanctions_list_sources` renders each configured URL as a link to itself, and the coverage and `Screened:` lines of `sanctions_get_entity` and the reporting-exception and node-screening lines of `sanctions_trace_ownership` close the list above them instead of rendering inside it.
- **Strict completion** ([#98](https://github.com/cyanheads/sanctions-screening-mcp-server/issues/98)): each distinct query word takes its own name word, one to one; a sound match also needs a Jaro-Winkler of 0.65 or more, and a stoplisted name word covers a query word only when identical (`PING AN` no longer returns `Bank of Industry and Mine`). A one-letter query word, as the fold makes of `A-Emmeh` or `70.º`, may pair with a stoplisted name word, and a romanized query word counts as the native word it spells (`Мэр Мер` needs two name words).
- **Refresh outcome** ([#100](https://github.com/cyanheads/sanctions-screening-mcp-server/issues/100)): a sanctions refresh rebuilds the name and identifier indexes and records each list's outcome before it commits `complete` or `error`, so every process reads `in_progress` until then, and `sanctionsAsOf` and readiness move only afterward.
- **Cross-reference guidance** in `sanctions_get_entity` and `sanctions_trace_ownership` says a name re-screen can add approximate matches, and no longer limits that to lists with no strict match (wrong for the UK and UN lists).
