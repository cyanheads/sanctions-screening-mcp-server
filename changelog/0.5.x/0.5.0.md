# 0.5.0 — 2026-10-03

Upgrading: run `bun run mirror:refresh` once. The OFAC date, `features`, `legalBasis`, and placeholder-identifier fixes reach an existing mirror only through a sanctions refresh; until then `sanctions_get_designation` returns `features: []` and a stored `N/A` / `n.a.` placeholder still matches in `sanctions_screen_identifier`. The first open of a mirror an earlier release wrote rebuilds the sanctions name index (about 4 s on the 2026-10-03 lists) and runs the GLEIF store migration (about 1.5–2 s); `mirror:verify` performs the same upgrade. The GLEIF exact-name index (`lei_name_normalized_idx`, about 12–14 s and +90 MB) is built only by `mirror:init`, `mirror:refresh`, and `mirror:seed`, never inside a request. Counts change with grouping and the removed caps: on the 2026-10-03 lists strict `al` returns 2,344 hits, `company` 4,387, and fuzzy `internashional` 729. Rolling back to 0.4.0 is safe: it reads its released name index, and the next 0.5.0 open rebuilds the index after any sync 0.4.0 ran.

## Added

- **`sources`** on every sanctions hit of `sanctions_screen_name`, `sanctions_screen_identifier`, `sanctions_get_entity`, and `sanctions_trace_ownership` ([#61](https://github.com/cyanheads/sanctions-screening-mcp-server/issues/61)): every selected list the hit's party is on, `ofac_sdn` and `ofac_consolidated` together for an OFAC party both files publish under one entry ID.
- **`fuzzySources`** enrichment on `sanctions_screen_name` ([#59](https://github.com/cyanheads/sanctions-screening-mcp-server/issues/59)): the lists a fuzzy pass searched.
- **`matchedOn`, `matchedIdentifiers`, and `sanctionsScreen.screenedInputs`** on `sanctions_get_entity` and `sanctions_trace_ownership` ([#37](https://github.com/cyanheads/sanctions-screening-mcp-server/issues/37), [#56](https://github.com/cyanheads/sanctions-screening-mcp-server/issues/56)): which of the entity's names or identifiers produced each hit, and what was screened beyond the legal name and LEI.
- **`invalid_lei_checksum`** (`InvalidParams`, −32602) on `sanctions_get_entity`, the `sanctions_trace_ownership` root, and `sanctions://entity/{lei}` ([#62](https://github.com/cyanheads/sanctions-screening-mcp-server/issues/62)): an LEI the mirror lacks whose ISO 17442 check digits fail. A valid one stays `lei_not_found`.
- **`features`** on `sanctions_get_designation` and `sanctions://designation/{source}/{entryId}` ([#64](https://github.com/cyanheads/sanctions-screening-mcp-server/issues/64)): OFAC's descriptive features (vessel flag, type, and tonnage, aircraft model and operator, title, gender, sanctions notes) and UK ship details, typed by each list's label. No screening tool matches them.
- **`reachedVia: "ultimate"`** on `sanctions_trace_ownership` nodes ([#58](https://github.com/cyanheads/sanctions-screening-mcp-server/issues/58)): a node only an `IS_ULTIMATELY_CONSOLIDATED_BY` edge reaches within `depth`, returned as an unwalked leaf.
- **`relationshipCount` and `alternateNamesIndexed`** on `sanctions_list_sources` ([#25](https://github.com/cyanheads/sanctions-screening-mcp-server/issues/25)), and `alternateNamesIndexed` on `sanctions://sources`.
- **Bound notices** on `sanctions_screen_name` and `sanctions_resolve_entity` when a fuzzy pool's budget left names unscored, and on `sanctions_resolve_entity` when its strict scan reached its 2,000-name bound ([#9](https://github.com/cyanheads/sanctions-screening-mcp-server/issues/9)). `mirror:verify` adds `exactNamesIndexed`.

## Changed

- **Strict `sanctions_screen_name` completes each selected list it found nothing on with a fuzzy pass** (#59), adding only candidates that cover every word but legal forms, articles, and `uk`/`usa`/`uae`/`rf`, after the strict hits. Such screens report `lower_bound`; `matchModeUsed` is `fuzzy` only when every selected list was fuzzy-searched.
- **An OFAC party both OFAC files publish is one hit** (#61), grouped before counting and paging, so hit counts drop. `source` is the record the hit's fields come from: `ofac_sdn`, unless the Consolidated record matched better.
- **The entity cross-reference screens every other and transliterated name strict and looks up the LEI and registration number as non-document identifiers** (#37, #56). The registration number matches only identifiers published for the entity's jurisdiction country; hits merge per designation before the cap, and an identifier-only hit has no `matchedName` or `matchType`.
- **`direction: "both"` walks the root's parents and children only** ([#38](https://github.com/cyanheads/sanctions-screening-mcp-server/issues/38)), never siblings or co-parents. Ultimate-parent edges no longer count as a hop (#58), and every edge joins two returned nodes.
- **`sanctions_trace_ownership` renders a node without potential matches on one line** ([#65](https://github.com/cyanheads/sanctions-screening-mcp-server/issues/65)).
- **`sanctions_list_sources` and `sanctions://sources` serve one payload** (#25): the `gleif` row's `url` is the configured `GLEIF_GOLDEN_COPY_BASE_URL` alone, and `gleifBaseUrl` is removed.
- **Ties order by list, then entry ID numerically** ([#60](https://github.com/cyanheads/sanctions-screening-mcp-server/issues/60)): `2677` sorts before `26079`.
- **Strict resolution reads names equal to the query first** through `lei_name_normalized_idx` when its 2,000-name scan reaches the bound (#9), on a mirror whose scripts built the index.
- **GLEIF store schema version 2 drops `lei_entity_status_idx`** ([#52](https://github.com/cyanheads/sanctions-screening-mcp-server/issues/52)), which no resolution query read, on first open.
- **The sanctions name index splits into `name_fts` and `name_blocking_fts`**: strict matching reads `name_fts` in its released shape, fuzzy blocking the new index, and a stamp rebuilds both after any sync an earlier release ran.
- **Declared `recovery` hints reach the wire from the framework**; handlers no longer forward `ctx.recoveryFor`.
- **Docker**: production dependencies install in a `deps` stage on `$BUILDPLATFORM` (`scripts/install-otel.ts`, `scripts/prune-musl-packages.ts`), and `MCP_FORCE_CONSOLE_LOGGING` is gone.
- **`server.json`** npm entries launch the bin through `npx`, without `run start:*`; the HTTP entry fixes `MCP_TRANSPORT_TYPE` to `http`.
- **Repo**: CodeQL runs per language, `package.json` `files` excludes `dist/*.mcpb`, and `.env.example` and the README document `LOG_TOOL_FAILURE_PAYLOADS`.

## Removed

- **`SANCTIONS_FUZZY_MAX_RESULTS`** (#9): fuzzy results are uncapped.

## Fixed

- **Paging reaches every match a pass counts** (#9): the 50-result fuzzy cut and the 5,000-row strict screening cap are gone, and `hasMore` / `nextOffset` describe pages only.
- **Fuzzy blocking reads an index** ([#50](https://github.com/cyanheads/sanctions-screening-mcp-server/issues/50)) instead of a `LIKE` scan per query word, and its phonetic lookup matches per word, reaching multi-word names ([#68](https://github.com/cyanheads/sanctions-screening-mcp-server/issues/68)).
- **Each selected list pools fuzzy candidates under its own 2,000-name budget** ([#54](https://github.com/cyanheads/sanctions-screening-mcp-server/issues/54)), whole blocks smallest first, so table order and the other selected lists no longer decide what is scored.
- **`sanctions_resolve_entity` pools LEIs by the same rule** ([#51](https://github.com/cyanheads/sanctions-screening-mcp-server/issues/51)), and the pass for a mirror without the GLEIF name index scans at most three prefixes ([#71](https://github.com/cyanheads/sanctions-screening-mcp-server/issues/71)).
- **Legal forms, articles, and bare jurisdiction codes no longer count toward fuzzy admission or key a blocking lookup** ([#55](https://github.com/cyanheads/sanctions-screening-mcp-server/issues/55)), `FUZZY_STOPLIST`.
- **OFAC designation dates come from the earliest entry on the file's own lists** ([#63](https://github.com/cyanheads/sanctions-screening-mcp-server/issues/63)), so a party's `ofac_sdn` and `ofac_consolidated` records can differ.
- **`legalBasis` is populated** ([#66](https://github.com/cyanheads/sanctions-screening-mcp-server/issues/66)): OFAC's legal-basis references, the EU regulation title, and the UK regime's regulations, several joined with `; `. The UN list publishes none.
- **`N/A` and `n.a.` placeholders are no longer indexed as identifiers** ([#67](https://github.com/cyanheads/sanctions-screening-mcp-server/issues/67)).
