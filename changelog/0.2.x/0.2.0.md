# 0.2.0 — 2026-09-24

Upgrading: an existing sanctions mirror picks up entity decoding, the new fold, and the designation details on its next refresh (the HTTP cron or `mirror:refresh`), and that refresh also starts pruning delisted designations, at most half of a source per run. An existing GLEIF mirror keeps its old `normalized_name` and undecoded text until a full `mirror:init`.

## Changed

- **`sanctions_screen_name` and `sanctions_resolve_entity` reject a name with no letter or digit** as `name_not_searchable` (`InvalidParams`), where they returned a zero-hit success with `normalizedQuery: ""`. The internal cross-reference screens still answer such a legal name with no hits.
- **`mirror:init` over a populated mirror prunes** the same way a refresh does.

## Fixed

- **`fold()` keeps the letters and digits of every script** ([#20](https://github.com/cyanheads/sanctions-screening-mcp-server/issues/20)): native-script names are indexed and match native-script queries, and an ASCII fold is unchanged. Double Metaphone keys only all-Latin tokens, so homoglyph residue no longer yields a blocking key.
- **XML entity references are decoded once, at parse time** ([#21](https://github.com/cyanheads/sanctions-screening-mcp-server/issues/21)): the five predefined entities and numeric references no longer reach stored names, aliases, remarks, or the `name` index, so `Greenland Oil & Gas Trading FZE` screens `exact`. `processEntities` stays off; unknown and out-of-range references stay literal.
- **`sanctions_get_designation` returns the identifiers, addresses, dates and places of birth, and nationalities each source publishes** ([#22](https://github.com/cyanheads/sanctions-screening-mcp-server/issues/22)). Placeholders (`UNKNOWN`, `na`, OFAC `undetermined`) read as absence, and separately listed dates and places pair only when the record publishes one of each.
- **A refresh removes designations a source stopped publishing** ([#30](https://github.com/cyanheads/sanctions-screening-mcp-server/issues/30)) from `designation` and the `name` index, once its complete document parsed. A run that would remove more than half of a source's stored rows (`MAX_PRUNE_SHARE`), including a document with no accepted record, removes nothing and logs a warning.
- **A sanctions document that ends before its root element closes fails that source's harvest** (`ServiceUnavailable`) instead of ingesting the records before the cut.
- **Fuzzy blocking prefixes, Jaro-Winkler, and the length ratio count code points** ([#31](https://github.com/cyanheads/sanctions-screening-mcp-server/issues/31)), so a supplementary-plane letter never becomes a lone surrogate in a `LIKE` pattern and scores like its BMP twin.
- **The mirror lifecycle scripts print their counts.** Log fields ride the run's request context; `mirror:init` and `mirror:refresh` report `removed`, and `mirror:verify` reports `lastError`.

## Security

- **`fold()` cost was quadratic on caller-supplied names**: a long run of combining marks took about 4.9 s at 80k characters on the request path. Marks are now stripped before NFKD, so the fold is linear.
- **Name inputs had no length bound**: a name of 2,000 distinct short words held one `sanctions_screen_name` call for about 79 s. Both name tools now reject a name past 64 words or 1,024 characters as `name_too_long` (`InvalidParams`), checked in the handler so the advertised input schema is unchanged.
