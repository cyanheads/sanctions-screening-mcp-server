# 0.1.6 — 2026-07-04

## Changed

- **`mirror:init`** streams the GLEIF golden-copy ingest — ZIP/gzip decompression, record-boundary scanning, and batched insert-only ingest with progress logging — instead of buffering the whole decompressed document in memory. ([#6](https://github.com/cyanheads/sanctions-screening-mcp-server/issues/6))
- **`SANCTIONS_REFRESH_CRON`** wording (config description, `.env.example`, README, `docs/design.md`) now matches what the cron actually refreshes: the sanctions lists + name index. GLEIF deltas are not on the cron — run `mirror:refresh` manually. ([#5](https://github.com/cyanheads/sanctions-screening-mcp-server/issues/5))

### Dependency bumps

- `@cyanheads/mcp-ts-core` `^0.10.9` → `^0.10.10`
- `@biomejs/biome` `2.5.0` → `2.5.2`
- `@types/node` `26.0.0` → `26.1.0`
- `tsc-alias` `^1.8.17` → `^1.9.0`

## Fixed

- **`ScreeningService.runFuzzy()` / `runLeiFuzzy()`** gate fuzzy admission on whole-query or token-coverage support instead of the single best token pair — a multi-token query is no longer admitted on one strong token-to-alias match. Surfaced scores stay the raw Jaro-Winkler value. ([#4](https://github.com/cyanheads/sanctions-screening-mcp-server/issues/4))
- **GLEIF delta refresh** now advances the LEI mirror's freshness state after a successful apply, so `sanctions_list_sources` / `sanctions://sources` report the data just loaded; guarded so a delta on a never-initialized mirror can't flip it to ready, and `total` reflects the live entity count rather than the delta batch size. ([#5](https://github.com/cyanheads/sanctions-screening-mcp-server/issues/5))
- **`resolveGleifFileUrl()`** reads the GLEIF golden-copy index's delta files from the correct nesting — `delta_files.{window}`, not `delta_files` directly. ([#5](https://github.com/cyanheads/sanctions-screening-mcp-server/issues/5))
- **`src/services/screening/xml.ts`** sets `removeNSPrefix: true` on the shared XML parser, so namespace-prefixed real GLEIF records (`lei:`/`rr:` on every element) parse completely instead of returning zero entities and dropping every relationship. Dead prefixed-key fallbacks in `gleif-ingest.ts` retired. ([#7](https://github.com/cyanheads/sanctions-screening-mcp-server/issues/7))

## Security

- **`js-yaml` `3.14.2` → `3.15.0`** (transitive, via `depcheck`) — clears [GHSA-h67p-54hq-rp68](https://github.com/advisories/GHSA-h67p-54hq-rp68), a moderate quadratic-complexity denial-of-service in merge-key handling. Resolved by the `@cyanheads/mcp-ts-core` bump and lockfile re-resolve; `bun audit` goes from 1 finding to 0.
