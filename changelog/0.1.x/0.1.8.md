# 0.1.8 — 2026-08-16

## Added

- **`offset`** input on `sanctions_screen_name` and `sanctions_resolve_entity`, alongside `totalAvailable`, `totalAvailableBasis`, `hasMore`, and `nextOffset` enrichment. An offset past the end returns an empty page with a notice naming the true total, never an error. ([#9](https://github.com/cyanheads/sanctions-screening-mcp-server/issues/9))
- **`mirror_not_ready`** declared on `sanctions://designation/{source}/{entryId}` and `sanctions://entity/{lei}` (`ServiceUnavailable`, retryable). ([#11](https://github.com/cyanheads/sanctions-screening-mcp-server/issues/11))
- **`SOURCE_LICENSES`, `sourceUrls()`, `gleifSourceUrl()`** in `_shared.ts` — one provenance table read by both `sanctions_list_sources` and `sanctions://sources`, so the two cannot drift as sources are added or licenses change. ([#12](https://github.com/cyanheads/sanctions-screening-mcp-server/issues/12))
- Vitest `smoke`, `fuzz`, and `integration` projects, previously scaffolded as comments, now covering the registered surface, XML-ingest and matcher fuzzing, `format()` parity, matching and ownership correctness, and the offline upstream download boundary. `bun run test:coverage` runs the suite under istanbul.
- `.gitattributes` plus `.github/` `CODE_OF_CONDUCT.md`, `CONTRIBUTING.md`, `SECURITY.md`, and `FUNDING.yml`.

## Changed

- **`tsconfig.json`** typechecks `src` and `tests` under `noEmit`; emit moves to `tsconfig.build.json` (`rootDir: src`).
- **`bunfig.toml`** holds packages published in the last 3 days (`minimumReleaseAge`, framework excluded) and runs the Socket install scanner; `devcheck`'s outdated gate no longer fails on peer rows or on a version a hold pins at Current.
- **`Dockerfile`** pins `oven/bun:1.3.14`, mounts a BuildKit cache for Bun's install cache, and installs production and OTEL dependencies with `--omit=peer`.
- `README.md` documents the paging contract on both screening tools; `docs/design.md` records that a fuzzy-mode result count is a floor, not a total.

## Fixed

- **`sanctions_screen_name` / `sanctions_resolve_entity`** no longer present a truncated count as the total: `ScreeningService` carries the pre-slice count out to the tool, and `totalAvailableBasis` marks it `exact` only for a strict pass that stayed under its raw-row scan cap. Every fuzzy pass reports `lower_bound`, since that candidate pool is blocked and truncated to `SANCTIONS_FUZZY_MAX_RESULTS` before it merges with the strict hits. ([#9](https://github.com/cyanheads/sanctions-screening-mcp-server/issues/9))
- **`runStrict()` / `runFuzzy()` / `runLeiStrict()` / `runLeiFuzzy()`** break same-band and same-score ties on `designationId` / `lei`, giving the total order offset paging needs — previously tied hits fell back to incidental row-arrival order, so pages could overlap or drop rows. ([#9](https://github.com/cyanheads/sanctions-screening-mcp-server/issues/9))
- **`sanctions://designation/{source}/{entryId}` and `sanctions://entity/{lei}`** check readiness before lookup and throw `mirror_not_ready`, instead of reporting a valid id as `designation_not_found` / `lei_not_found` against a never-synced corpus. Each gates on its own mirror — sanctions for the designation resource, GLEIF for the entity resource. ([#11](https://github.com/cyanheads/sanctions-screening-mcp-server/issues/11))
- **`sanctions://sources`** carries the per-source `url` and `license` that `sanctions_list_sources` returns, for the five sanctions sources and the synthetic `gleif` row. ([#12](https://github.com/cyanheads/sanctions-screening-mcp-server/issues/12))
