# 0.1.10 — 2026-08-16

## Changed

- **Every sanctions source streams.** `fetchXml`'s whole-document `await response.text()` is gone; each source is now scanned for complete record fragments and parsed one record at a time, yielding 2,500-row pages into the mirror. Peak resident memory on a synthetic 125 MiB document falls from 2260 MiB to 274 MiB, and the sanctions leg of a live `mirror:init` peaks at 480 MiB where it previously OOM-killed the run before GLEIF started. ([#13](https://github.com/cyanheads/sanctions-screening-mcp-server/issues/13))
- **`decodeUtf8Stream` / `scanRecordFragments`** moved from `gleif-ingest.ts` into a new `xml-stream.ts` and take a list of record element names, so the sanctions and GLEIF ingests share one scanner. The scanner assumes flat repeating record siblings — documented in that module, and true of every source this server reads.
- **`rebuildNameIndex()`** walks `designation` in keyset slices of 2,000 rows instead of materializing the table; the rebuild still runs inside one transaction.
- **`README.md` and `scripts/mirror-init.ts`** no longer call the sanctions lists small or light next to GLEIF: they total roughly 172 MB, of which OFAC `SDN_ADVANCED.XML` is about 120 MB on its own.

## Fixed

- **A record with no source identifier is dropped, not assigned one.** `parseOfacStandard`, `parseOfacAdvanced`, `parseEuEntity`, `parseUkDesignation`, and `parseUnEntry` each fell back to `crypto.randomUUID()`; since the mirror keys on `${source}:${sourceEntryId}` and the sync yields no tombstones, every harvest inserted another permanent row for the same malformed record and a screen could return one entity several times over. ([#14](https://github.com/cyanheads/sanctions-screening-mcp-server/issues/14))
- **A record with no usable name is dropped, not indexed under a placeholder.** The `'Unknown'` fallbacks in `parseOfacStandard` and `parseOneLei` are gone, and `isUsableName` also rejects a name carrying U+FFFD from a lossy decode, so a decode artifact no longer enters the `name` index as an alias. ([#14](https://github.com/cyanheads/sanctions-screening-mcp-server/issues/14))
- **Drops are counted per source rather than absorbed silently.** Each harvest tallies `missingIdentifier` and `unusableName`; the sanctions sync logs the tally as each source completes, and `mirror:init` / `mirror:refresh` log the GLEIF Level 1 tally alongside the record count. ([#14](https://github.com/cyanheads/sanctions-screening-mcp-server/issues/14))
- **OFAC `program` and `designationDate` survive the streaming rewrite.** `SDN_ADVANCED.XML` publishes its `<SanctionsEntries>` block after every `<DistinctParty>`, so a forward pass cannot attach the fields inline; they accumulate behind the party stream and are applied as an `UPDATE` keyed on `source_entry_id` once the source's rows have landed. A live `mirror:init` ingests 33,259 designations with OFAC programme coverage at 19,680/19,680. ([#13](https://github.com/cyanheads/sanctions-screening-mcp-server/issues/13))
