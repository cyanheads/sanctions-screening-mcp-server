# 0.3.0 — 2026-09-25

Upgrading: an existing sanctions mirror migrates on first open (schema version 2 adds `designation.reference_number`) and builds its identifier index from the stored records, so `sanctions_screen_identifier` answers without a re-init; a migrated mirror still opens under 0.2.0. Reference numbers, the new identifiers, and the new date forms arrive only with the next sanctions refresh, so run `mirror:refresh` after upgrading rather than waiting for the HTTP cron.

## Added

- **`sanctions_screen_identifier`** ([#41](https://github.com/cyanheads/sanctions-screening-mcp-server/issues/41)): exact, unscored lookup of an identifier across every loaded list, `type` `any` (default), `imo`, `swift_bic`, `digital_currency_address`, `passport`, or `national_id`. Spacing, case, and `-./` are ignored; BIC compares on eight characters, and a wallet folds case only for hex, bech32, and cashaddr.
- **`referenceNumber`** ([#42](https://github.com/cyanheads/sanctions-screening-mcp-server/issues/42)) on `sanctions_get_designation`, `sanctions://designation/{source}/{entryId}`, and `sanctions_screen_name` hits: UN `REFERENCE_NUMBER`, EU `euReferenceNumber`, UK OFSI Group ID. Text output adds `| **Reference:** …`.

## Changed

- **`entryId` resolves published reference numbers** on `sanctions_get_designation` and the designation resource (#42), trimmed and case-insensitive, entry ID first. A reference several designations share fails as `reference_ambiguous` (`InvalidParams`) naming each `sourceEntryId`; not-found now reads `… with entry ID or reference number "X"`.
- **`datesOfBirth[].date` is ISO 8601 at the precision the source published** ([#39](https://github.com/cyanheads/sanctions-screening-mcp-server/issues/39)): OFAC's `YYYY-01-01` and `YYYY-MM-01` become `YYYY` and `YYYY-MM`, ranges become intervals (`1955/1957`, `../1980`), and UK `DD/MM/YYYY` becomes ISO. New `circa: true` marks a date its source flags approximate.
- **`designationDate` is the source's own designation date as `YYYY-MM-DD`** (#39, [#46](https://github.com/cyanheads/sanctions-screening-mcp-server/issues/46)): UK and UN values are reformatted (UN drops a UTC offset), EU reads the entity's `@designationDate` rather than its latest regulation's publication date, UK never falls back to `LastUpdated`, and the OFAC standard-format path no longer infers one from remarks. Absent where the source publishes none.
- **`identifiers` carry more of what each list publishes** ([#40](https://github.com/cyanheads/sanctions-screening-mcp-server/issues/40), [#45](https://github.com/cyanheads/sanctions-screening-mcp-server/issues/45)): OFAC advanced adds identifier-class features (SWIFT/BIC, digital-currency addresses, vessel call signs, aircraft tail and serial numbers, phone, email, website, …) typed by OFAC's label; UK adds phone numbers, emails, and websites. The OFAC standard-format path (#46) keeps only identity-document and identifier-class `idList` entries, dropping gender, sanctions notes, and vessel descriptors, and adds `Vessel Call Sign`.
- **Docs:** `README.md` and `docs/design.md` cover the identifier tool and index, reference-number resolution, published-precision dates, per-source refresh failures, the sync time bound, and the in-place mirror upgrade.

## Fixed

- **A failing source no longer stops a sanctions refresh** ([#32](https://github.com/cyanheads/sanctions-screening-mcp-server/issues/32)): it keeps its rows and prunes nothing, every other source still refreshes, and the name and identifier indexes are rebuilt. The run then fails with `Sanctions harvest failed for <codes> (n of 5 sources); …`, so `sanctionsAsOf` advances only when every source refreshed and the mirror scripts exit non-zero.
- **The HTTP refresh cron runs under a time bound** ([#43](https://github.com/cyanheads/sanctions-screening-mcp-server/issues/43)), 4 hours like `mirror:refresh` (`REFRESH_HOURS`). A run the bound ends fails as a `Timeout` naming the source it stopped in (`Sanctions harvest of <source> did not finish. …`), and the next tick runs instead of being skipped as an overlap.
- **Source downloads bound only the wait for response headers** ([#47](https://github.com/cyanheads/sanctions-screening-mcp-server/issues/47)), at 120 s (`<source> sent no response headers within 120 s.`), so a transfer longer than two minutes drains until it ends or the run's bound stops it.
- **The designation resource percent-decodes `entryId` once** ([#44](https://github.com/cyanheads/sanctions-screening-mcp-server/issues/44)); a malformed escape resolves to `designation_not_found`.
- **The completeness check accepts trailing comments and processing instructions of any length** ([#34](https://github.com/cyanheads/sanctions-screening-mcp-server/issues/34)) after the root close. A self-closing root followed by text or an element, and a stream cut inside a comment or CDATA after a literal root end tag, now fail.
